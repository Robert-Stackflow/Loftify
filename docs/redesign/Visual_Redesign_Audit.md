## 3. 现状问题清单

### 3.1 色彩与层级

1. `ChewieThemeColorData` 同时承担预设色、组件色和语义色，但 `ColorScheme` 只覆盖部分角色；页面底色、内容底色、输入层、悬浮层、选中层和禁用层缺少稳定的一一映射。
2. 浅色页面已经按产品要求保持白色，但灰色卡片、输入层和 Caption 区域的灰度、边框与分隔线强度不一致，容易形成“很多浅灰盒子叠在白底上”的脏乱感。
3. `ChewieColors` 中点赞、收藏、分享等功能色较多。高频互动如果同时使用各自彩色，会和作品图片争夺注意力；未来只允许当前选中态或危险状态使用强调色。
4. 深色主题存在多个不同黑灰起点，阴影直接复用黑色会失去层级；需要以边界、亮度差和极弱环境阴影共同表达。
5. 自定义主题必须改变强调色而不是破坏内容底色、正文对比度或危险色含义。

### 3.2 字体与阅读

1. TextTheme 已经集中定义，但仍偏 Material 通用模板：显示级 57 / 45 / 36 基本不服务当前内容产品，而卡片标题、作者、标签、元信息和按钮又依赖局部 `apply` 叠加。
2. 页面标题、区块标题和卡片标题在不同页面经常只靠字重区分，字号和行高关系不稳定；中英文混排时基线与视觉重量变化明显。
3. 长文正文目前沿用普通正文思路，缺少独立的阅读宽度、17px 左右字号、1.75～1.85 行高、段落节奏、引用和图片说明语义。
4. 次要文字存在过浅风险；低对比元信息在浅色图片密集页面和深色模式中都容易消失。
5. 大字体时仍有固定高度页面残留。`DYNAMIC-01` 已证明仅以当前字号调通并不可靠，后续组件默认必须内容驱动高度。

### 3.3 间距、栅格与响应式

1. 业务层 329 处直接 EdgeInsets 表达，4、5、6、8、10、12、15、16、18、20 等近邻数值并存，页面节奏无法形成清晰重复规律。
2. 当前断点同时存在 380、480、500、600×900、700 等页面级判断；“平板/桌面”更多由平台与方向决定，而不是统一的可用宽度和内容最大宽度。
3. 手机瀑布流内容很满，标题、标签、作者、热度和菜单同时出现；平板横屏则容易把过多列铺满整屏，缺少内容最大宽度和密度上限。
4. 设置、管理页适合低密度分组；首页、搜索适合高密度内容流；个人主页与详情适合中密度。当前没有显式密度等级。
5. 键盘、安全区、系统手势区已有局部处理，但需要由页面框架统一提供而不是每页重复计算。

### 3.4 圆角、边框与阴影

1. 15 种圆角数值会让卡片、图片、标签、输入框、Panel 和 Dialog 的角色关系模糊。
2. 某些区域同时使用灰底、描边、阴影和圆角，层级信号重复；另一些可点击区域只有透明 GestureDetector，没有焦点或按下反馈。
3. 圆角 50 / 99 被当作“胶囊”的数值技巧，需要替换为明确的 full/pill 语义。
4. 图片圆角必须服务裁切边界，Panel 圆角必须服务空间层级；不能因为统一而让所有内容都变成同一个圆角盒子。

### 3.5 图标、交互与动效

1. Lucide 迁移已经完成，后续重点从“换图标”转为统一视觉尺寸、文字基线、选中容器和语义状态。
2. 87 个业务 GestureDetector 说明点击反馈仍分散。瀑布流卡片无水波纹是已确认规则，但设置项、菜单、按钮等需要统一 hover / press / focus；不能全局机械添加水波纹。
3. 业务层 63 处动画时长覆盖太多档位。90ms 按下、180ms 状态、220ms 页面、260ms Panel、280ms 内容进入足以覆盖绝大多数场景。
4. 减少动画、降低透明度和高对比度已有部分链路，阶段 B 必须成为每个公共动效/玻璃组件的默认分支。
5. Lottie 只承担不可测的加载状态；下载图片、视频和文件必须继续展示确定进度，不能再次替换成 Lottie。

### 3.6 内容呈现

1. 首页作品卡片中封面、标题、标签、作者、热度和更多菜单常处于相近视觉权重，内容层级不足。
2. 搜索热榜、推荐词和历史记录使用不同分组方式；热榜大灰卡容易比搜索本身更重。
3. 动态的关注、标签、合集和粮单具有不同信息结构，但需要共享作者/封面/摘要/状态/操作的节奏。`DYNAMIC-01` 前的固定高度是典型反例。
4. 个人主页头图、身份信息、统计、主操作和 Tab 目前信息完整，但头图区很重，容易压缩首屏作品空间。
5. 帖子详情的正文已可读，但 AppBar 信息、作者区、正文、合集/粮单提示、浮动操作和评论边界仍需以“阅读模式”重新组织视觉权重。
6. 评论区不应重新添加整块灰底；优化重点是头像、昵称、回复关系、正文、时间和操作的垂直顺序。

## 4. 两套完整视觉方向

### 方向 A：静谧内容工作室（Quiet Content Atelier）— 选定

核心比喻是“白色工作台上摆放作品集”。页面框架安静、低噪声，作品本身提供绝大多数色彩；界面使用现有青绿色强调色建立 Loftify 自身识别，不模拟 LOFTER 官方视觉。

| 维度 | 方案 |
| --- | --- |
| 浅色 | 页面与主导航保持纯白；内容层使用接近白色的中性暖灰，边界比阴影更常用 |
| 深色 | 非纯黑的中性墨色页面，内容层只提高少量亮度，避免大块发灰或黑洞感 |
| 强调 | 默认延续 Loftify 青绿；只用于选中、主要动作、链接和进度，不制造彩色按钮墙 |
| 字体 | 系统字体 / 用户字体保持可切换；以清晰无衬线为主，长文通过字号、行高和宽度建立文艺感，不强制装饰字体 |
| 形态 | 图片 12～14px、卡片 14px、Panel 24px；标签使用 6～10px 或胶囊语义，不把所有容器都做成大圆角 |
| 层级 | 白底、内容面、悬浮面三层；普通内容优先留白与分隔，只有真实悬浮物使用阴影 |
| 动效 | 轻、短、跟手；图片和阅读过渡强调连续性，状态切换强调结果，不做循环装饰 |
| 密度 | 首页/搜索高密度，详情/主页中密度，设置/管理低密度，共享 Token 但使用不同布局配方 |
| 可访问性 | 44×44 最小点击区、文本对比度目标 WCAG AA、选中态同时使用颜色与形态 |

优势：最大限度保持用户已经确认的白色浅色背景、青绿主题、毛玻璃导航和内容优先；对摄影、绘画、同人、文字等内容类型都中性；自定义主题与深色模式容易稳定派生。  
风险：如果留白和层级控制不精确，会显得普通或空。必须依靠字体节奏、栅格、细边界和内容裁切质量体现精致度。

### 方向 B：编辑画廊（Editorial Gallery）— 未选

核心比喻是“独立杂志与展览目录”。使用更强的标题尺度、细分隔线、较小圆角和更严格的版心，让文学、摄影与专题合集具有编辑感。

| 维度 | 方案 |
| --- | --- |
| 浅色 | 纸张暖白作为主底，纯白作为图片和高价值内容的展板 |
| 深色 | 深蓝墨色页面与偏暖白正文，形成印刷品式对比 |
| 强调 | 墨绿或暗朱红作为单一编辑标记，标签和序号更接近目录符号 |
| 字体 | 标题可使用用户选择字体的较强字重，长文可引入受控衬线回退；元信息使用紧凑无衬线 |
| 形态 | 6～10px 小圆角、更多细线和编号，Panel/导航仍保留较大空间圆角 |
| 层级 | 更少灰卡，更多版心、留白、分隔线和跨栏图像 |
| 动效 | 类似翻页、目录定位和展品聚焦的空间连续性，时长略长但仍支持减少动画 |
| 密度 | 首页更像杂志拼版，专题/合集表现突出，设置页则保持编辑目录式分组 |

优势：辨识度强，长文、专题、摄影和合集展示有明显气质。  
风险：暖色页面不符合用户已多次确认的浅色纯白要求；衬线和强编辑网格会增加多语言、用户字体、瀑布流与自定义主题的适配成本，也更容易让框架压过作品。

### 选型结论

选择方向 A。吸收方向 B 的“长文版心、标题节奏、细分隔线和专题秩序”，但不引入暖纸主底、装饰性衬线或杂志式强拼版。这个决定同时满足：

- 浅色所有页面与主导航继续是白色。
- 现有青绿色成为独立第三方产品的克制识别，不冒充 LOFTER 官方。
- 内容图片仍提供主要色彩，主题系统不会与作品竞争。
- 既有自定义主题、字体、语言、深浅色和响应式逻辑可以平滑迁移。

## 5. 信息架构与入口冻结

最终重构只允许改变视觉层级和布局密度，下列信息与入口不得删除、隐藏或改写业务含义。

```text
Loftify
├─ 主导航
│  ├─ 首页：信息流、布局切换、刷新、帖子更多、作品详情
│  ├─ 搜索：搜索框、历史、猜你喜欢、热榜、搜索结果六类 Tab
│  ├─ 动态：关注、标签、合集、粮单四类 Tab
│  └─ 我的
│     ├─ 身份：头像、昵称、ID、文章/合集、热度、粉丝、关注
│     ├─ 内容中心：喜欢、推荐、收藏、足迹、下载管理
│     ├─ 我的创作：作品、合集、粮单
│     └─ 快捷操作：退出、主题、装扮、通知、设置
├─ 内容发现
│  ├─ 标签详情：推荐、最新、最热、筛选、合集/粮单、相关标签、装扮
│  ├─ 搜索结果：全部、标签、合集、粮单、文章、用户
│  └─ 收藏夹、喜欢、推荐、历史、合集与粮单列表
├─ 内容消费
│  ├─ 图片/图文/长文详情：作者、正文、标签、互动、合集/粮单、评论、切篇
│  ├─ 图片灯箱：原图、翻页、缩放、下拉退出、下载/链接
│  ├─ 视频：播放、进度、全屏、作者页、弹幕、倍速、长按菜单、下载
│  └─ 评论：热评、全部评论、多级回复、输入与分页
├─ 作者与关系
│  ├─ 个人主页：资料头、统计、关注/浏览器、作品/喜欢/推荐/合集/粮单
│  ├─ 粉丝、关注、支持者
│  └─ 黑名单、屏蔽标签、不看 TA 动态
├─ 资产与批量操作
│  ├─ 下载管理：活动任务、历史、暂停/继续/取消/重试/清理
│  ├─ 批量下载：选择、全选、解析、进度、失败重试、去重
│  └─ 装扮：主题背景、头像框、装扮、表情包及详情
└─ 系统与身份
   ├─ 设置：通用、外观、图片、LOFTER 基础、实验室、管理、关于
   ├─ 主题、语言、字体、刷新率、安全与锁屏
   └─ 登录：验证码、密码、邮箱、LOFTER ID、滑动验证
```

官方接口暂缓项仍保留在需求层：正文选区评论、区间绑定、划线高亮与定位、原文变更和重叠选区处理。最终视觉重构不得伪造可提交的划线评论入口。

## 7. 已冻结的设计语言骨架

以下数值是阶段 B Token 的实现合同；页面不得直接复制这些数字，应通过语义 Token 使用。

### 7.1 语义色目标

| 角色 | 浅色基准 | 深色基准 | 规则 |
| --- | --- | --- | --- |
| page | `#FFFFFF` | `#121412` | Scaffold、主滚动区、主导航的连续底色 |
| surface | `#F7F8F7` | `#191C1A` | 普通分组、输入层、低强调内容面 |
| surfaceRaised | `#FFFFFF` | `#202421` | Panel、Dialog、浮动操作和真实悬浮层 |
| textPrimary | `#202522` | `#F2F5F3` | 正文与标题，必须满足 AA |
| textSecondary | `#66706B` | `#AEB8B2` | 作者补充、时间、统计 |
| textMuted | `#8D9791` | `#839089` | 占位与低优先信息，不用于关键正文 |
| outline | `#E5E9E6` | `#303630` | 结构边界，默认 0.6～1px |
| accent | 默认延续 `#14C2BB` | 默认提高亮度 | 自定义主题可替换；选中态还需形态信号 |
| danger / warning / success | 独立语义 | 独立语义 | 不随自定义强调色漂移 |

最终颜色将由当前 `ChewieThemeColorData` 派生，不直接把默认青绿写死到页面。高对比度模式会提升文本和边界对比，降低透明度模式会把玻璃层替换为 `surfaceRaised`。

### 7.2 字体层级目标

| 角色 | 手机基准 | 说明 |
| --- | --- | --- |
| display | 28 / 1.25 / 700 | 极少量品牌或内容数字，不作为普通页面标题 |
| pageTitle | 20 / 1.30 / 700 | AppBar 与页面主标题 |
| sectionTitle | 16 / 1.35 / 650 | 区块和 Caption 标题 |
| cardTitle | 15 / 1.40 / 600 | 作品标题，通常 1～2 行 |
| body | 15 / 1.60 / 400 | 普通正文和说明 |
| readingBody | 17 / 1.80 / 400 | 长文正文，宽屏版心最大 720px |
| metadata | 12 / 1.45 / 400 | 时间、地点、热度、次要关系 |
| label | 13 / 1.30 / 600 | 按钮、标签与筛选 |

系统字体缩放不通过固定高度抵消；控件可增长，操作行必要时换布局而不是截断业务文案。自定义字体只替换家族，不破坏角色字号、行高和最大宽度。

### 7.3 间距、圆角与栅格目标

- 间距阶梯：2、4、6、8、12、16、20、24、32、40。
- 页面水平边距：小屏 12，普通手机 16，平板 24；正文与图片可按内容类型使用独立版心。
- 圆角：小控件 6，输入/标签 10，图片与普通卡片 14，Panel / Dialog 20～24，胶囊使用 `full` 语义。
- 内容沟槽：手机双列 8～10，宽手机/平板 12，桌面 16；列数由最小卡片宽度和最大内容宽度共同决定，不铺满无限宽屏。
- 宽度等级：compact `<600`、medium `600–839`、expanded `840–1199`、large `>=1200`。设备方向只影响布局选择，不替代可用宽度判断。
- 密度等级：`contentDense`（首页/搜索）、`contentComfortable`（详情/主页）、`controlComfortable`（设置/管理）。

### 7.4 边界、阴影与动效目标

- 普通内容默认不同时使用灰底、描边和阴影；优先留白，其次细边界。
- 悬浮导航/操作条使用一级环境阴影；Panel/Dialog 使用二级阴影；深色模式主要依靠亮度差和边界。
- 时长阶梯：press 90ms、state 180ms、page 220ms、panel 260ms、content 280ms。
- 曲线：进入 `easeOutCubic`，退出 `easeInCubic`，手势回弹使用受控弹性曲线；减少动画时全部收口到即时或极短淡化。
- Lottie、模糊、大图变换必须有重绘边界和性能降级；60/90/120Hz 使用真实时间而非逐帧增量。

## 8. 阶段 B/C 执行顺序与守卫

1. 建立颜色、字体、间距、圆角、阴影、栅格、密度和动效 ThemeExtension；现有主题与用户自定义强调色必须可派生。
2. 建立真实内容组件样板，覆盖中文/繁体/英文、长标题、大字体、无图、失败、禁用、加载和选中。
3. 先迁移按钮、输入、标签、卡片框架、设置项、菜单、Panel 和空/错/加载状态，再迁移页面。
4. 代表页面依次为：首页、帖子详情、标签详情、个人主页、设置。每个试点都保留真实数据、滚动、刷新、失败、空态与交互。
5. 页面族迁移顺序遵循总纲；每完成一族就运行全量测试、Android/Windows 构建、MuMu Hot Reload/Restart，并单独提交推送。

新增守卫：

- 新页面不得直接新增未登记的颜色、圆角、间距或时长数值。
- 媒体黑白遮罩、品牌标识、用户内容、代码高亮主题等例外必须登记角色和退出条件。
- 不以统一风格为由给瀑布流、Tab、评论区重新添加已明确取消的水波纹或灰色整块背景。
- 任何视觉迁移都要对照第 5 节入口清单，证明信息、数据、操作和返回路径没有遗漏。
